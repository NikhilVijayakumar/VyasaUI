**Finding: README-HOOK-001** | Minor

- Location: README.md — useDataState export description
- Issue: If `apiCall` does not return a `ServerResponse` (plain object, thrown error, non-conforming promise), `execute` catches the exception and produces `COMPLETED / isError: true / status: 500`. This invariant is critical — without it, consumers don't understand why they get an unexpected 500 error.
- Evidence: `feature/use-data-state.md` Invariants: "apiCall must return a ServerResponse — non-conforming returns trigger the exception catch branch, producing COMPLETED / isError: true / status: 500"
- Recommendation: Add one-liner to useDataState export: "`apiCall` must return `ServerResponse` — non-conforming calls produce `COMPLETED / isError / status 500`"
