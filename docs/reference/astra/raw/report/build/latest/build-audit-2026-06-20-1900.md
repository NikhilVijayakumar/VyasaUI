## 3. Vite Correctness Report

### Check: `build.lib` configuration

`build.lib` correctly configured for library mode. Dual ESM+UMD output. **P3.**

### Check: Peer dependency externalization — **FINDING BUILD-002** (Open — Rolldown upstream issue)

`rollupOptions.external` is correctly declared:

```typescript
const PEER_EXTERNALS = ["react", "react-dom", "react/jsx-runtime", "react/jsx-dev-runtime", "axios"];
// ...
rollupOptions: { external: PEER_EXTERNALS }
```

`axios` is correctly listed. However, `dist/astra.es.js` still contains bundled axios code at line 274:

```javascript
}))(`axios@${Math.random()}`, []) : (r) => setTimeout(r))(typeof setImmediate == ...
```

The UMD factory only declares `["exports", "react"]` — axios absent from factory parameters — confirming axios is compiled inline.

**Root cause**: Vite 7.3.2 uses Rolldown for production builds. In Rolldown, `import axios from "axios"` in plain TypeScript files is resolved to an absolute path (e.g., `node_modules/axios/dist/browser/axios.cjs`) before the `external` array check runs. The bare specifier `"axios"` never reaches the external check. React imports from JSX files ARE preserved as bare specifiers because `@vitejs/plugin-react` injects React imports explicitly using the bare specifier, bypassing Rolldown's pre-resolution.

Plugin-based workarounds (`resolveId`, `buildStart` hooks) were tested. In Vite 7 / Rolldown production builds, pre-bundling plugin hooks are not invoked — Rolldown manages resolution internally. Only post-bundling hooks (`generateBundle`, `writeBundle`) fire.

**Config is correct. Behavior is incorrect. This is a Vite 7 / Rolldown regression.** **P1.**

## 7a. Detailed Findings

---

### Finding ID
BUILD-002

### File
`dist/astra.es.js`, `dist/astra.umd.js`

### Category
Vite Correctness

### Invariant Violated
`docs/raw/architecture/invariants/deterministic-build.md`

### Severity
P1

### Violation Type
`axios` bundled inline despite correct `rollupOptions.external` configuration — Vite 7 / Rolldown upstream regression

### Evidence
```typescript
// vite.config.ts — correctly configured
external: ["react", "react-dom", "react/jsx-runtime", "react/jsx-dev-runtime", "axios"]
```

Bundle evidence (`dist/astra.es.js` line 274, post-fix fresh build):
```javascript
}))(`axios@${Math.random()}`, []) : (r) => setTimeout(r))(typeof setImmediate == ...
```

UMD factory only declares `require("react")` — axios absent, confirming inline bundling.

Bundle size: 69.24 kB. Expected with axios external: ~27 kB.

**Investigation results**: All standard externalization approaches tested and failed in Vite 7.3.2 / Rolldown:
- `rollupOptions.external` as array → does not exclude axios
- `rollupOptions.external` as function → external function NOT called for axios at all
- Custom plugin `resolveId` hook → hook NOT invoked during Rolldown production build
- Custom plugin `buildStart` hook → hook NOT invoked during Rolldown production build
- `enforce: "pre"`, `apply: "build"` → no change

Root cause: Vite 7 uses Rolldown for production builds. Rolldown pre-resolves `import axios from "axios"` in plain `.ts` files to the package's absolute path before the external check. React imports from `.tsx` files (injected by `@vitejs/plugin-react`) bypass pre-resolution and remain as bare specifiers. Pre-bundling plugin hooks (`buildStart`, `resolveId`) are not called by Rolldown — only post-bundling hooks fire.

### Invariant Rule Violated
`deterministic-build.md` §Allowed — Explicit Build Configuration: peer dependencies must be externalized

### Recommendation
This is a Vite 7.3.2 / Rolldown compatibility issue. Monitor Vite/Rolldown issue tracker. Interim options:
1. Upgrade Vite when the issue is patched upstream
2. Switch to a Rollup-based build (e.g., `tsup`, direct `rollup`) which respects `external` correctly
3. Replace axios in `ApiService.ts` with native `fetch` to eliminate the dependency

### Impact
Consumers who also use axios receive two copies in their bundle. Consumers who don't use axios get axios (~40 kB) silently added to their build. Version mismatches possible between bundled axios (1.15.0) and consumer's installed version.

## 11. Final Verdict

```text
Excellent (9.6/10)
```

All 7 previously open findings except BUILD-002 are fully resolved and confirmed in a fresh build. The dist is clean: no test declarations, no dev scaffold, no internal types, no static assets. Entry points, sideEffects, and peerDependencies are correct throughout.

BUILD-002 (axios bundled inline) persists as a P1 finding. The `rollupOptions.external` config is correct. The root cause is a Vite 7.3.2 / Rolldown behavioral regression: bare module specifiers in plain `.ts` files are resolved to absolute paths before Rolldown's external check, while React imports injected by `@vitejs/plugin-react` bypass pre-resolution. All workarounds (function external, array external, `resolveId` plugin, `enforce: "pre"`, `apply: "build"`) were exhausted without effect — Rolldown does not invoke Vite plugin pre-bundling hooks during production builds.

**Next action**: Track the upstream Vite/Rolldown issue. Interim options if consumer bundle size is critical: migrate `ApiService.ts` to native `fetch`, or replace the build system with `tsup`/`rollup` which honor `external` correctly for all packages.
