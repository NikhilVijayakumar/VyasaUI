## 6. ESM/UMD Validity Report

### Check: `"type": "module"` field

`"type": "module"` is set. All `.js` files in the package are treated as ESM. **P3.**

### Check: `"main"` and UMD bundle exposure — **FINDING BUILD-001**

Two issues combined:

**Issue A:** `"main": "./dist/astra.es.js"` points to the ESM bundle. The `"main"` field is used by legacy tooling and CommonJS environments. With `"type": "module"` set, a CJS consumer attempting `require('astra')` gets the ESM bundle, which causes `ERR_REQUIRE_ESM` in Node versions prior to 22.

**Issue B:** `dist/astra.umd.js` is built (the config specifies `formats: ["es", "umd"]`) but is not referenced in any package.json field:
- `"main"` → `astra.es.js` (ESM)
- `"module"` → `astra.es.js` (ESM)
- `"browser"` → `astra.es.js` (ESM)
- `exports` all conditions → `astra.es.js` (ESM)

The UMD bundle exists in `dist/` but is unreachable via any documented package entry point. Consumers in global script environments (`<script>` tag, legacy bundlers) have no path to the UMD bundle.

Correct configuration:
```json
"main": "./dist/astra.umd.js",
"module": "./dist/astra.es.js",
"exports": {
  ".": {
    "types": "./dist/lib.d.ts",
    "import": "./dist/astra.es.js",
    "require": "./dist/astra.umd.js",
    "default": "./dist/astra.umd.js"
  }
}
```

**P1.**

### Check: `"require"` condition in exports

`"require": "./dist/astra.es.js"` — explicitly declares CJS support but delivers ESM. Node's CJS loader throws `ERR_REQUIRE_ESM` on Node < 22. This is covered under BUILD-001.

### Check: `"module"` field

`"module": "./dist/astra.es.js"` — correctly points to ESM bundle for bundlers that support this field (webpack, rollup, parcel). **P3.**

### Check: `"types"` field

`"types": "./dist/lib.d.ts"` — correctly points to generated type entry declaration. **P3.**

### Check: `"sideEffects"` field — **FINDING BUILD-003**

`"sideEffects"` field is absent from `package.json`. Without this field:

- Bundlers (webpack, rollup, parcel) assume ALL files have side effects
- Tree-shaking is disabled for the entire package
- Consumers who import only `useDataState` still get the full library in their bundle

Astra has no module-level side effects. The correct declaration:

```json
"sideEffects": false
```

**P1.**

### Check: `.mjs` vs `.js` extension consistency

Config generates `.js` extensions (`fileName: (format) => `astra.${format}.js``). `package.json` references `./dist/astra.es.js` and `./dist/astra.umd.js`. Extensions are consistent. **P3.**
