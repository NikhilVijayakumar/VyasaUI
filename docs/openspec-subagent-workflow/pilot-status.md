# Agent pilot status

The repository-local role files define coordinator, planner, implementer, knowledge and reviewer for Codex, Claude Code and OpenCode. The common instructions and task handoff are in `role-and-handoff-contract.md`. Codex registers roles in `.codex/config.toml` and loads role layers from `.codex/agents/`. Claude Code uses `.claude/agents/`; OpenCode definitions are in `.opencode/agents/` and inherit the configured model. Model identifiers are candidates and access must be confirmed in the active account. These definitions cannot override harness or user instructions, authorize actions, or guarantee delegation.

Codex role registration and role files have been parsed as TOML; an actual CLI role-discovery and native configuration-backed delegation has not yet been verified. A read-only Luna coordinator was started via the current collaboration harness. Its shell failed to start with `helper_unknown_error`; when provided checklist facts directly it returned a handoff but miscounted them as 8 complete and 9 pending. The supplied facts actually describe 9 complete and 8 pending. This is a pilot failure: the primary agent must independently check progress and evidence; this result does not demonstrate working project-role loading or reliable autonomous tracking.

Claude Code and OpenCode have not been execution-tested. The installed OpenCode 2.1.2 rejected `opencode agent list`; its actual project-agent discovery needs verification in that harness. Model selection, permissions and review isolation also need testing there. Role instructions express intended behavior; they do not enforce filesystem or tool restrictions by themselves.

Before relying on the pilot, use a fresh trusted Codex CLI session to verify registration, model availability, instruction loading, real file access, an interrupted handoff, failing-check recovery and progress accuracy. Test the other harnesses separately. Preserve the staged workflow documents and unrelated changes. The installer refuses to overwrite files and is not intended as an ongoing synchronization mechanism.
